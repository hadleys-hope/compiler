# 📄 FRONTEND.md: Архитектура фронтенда компилятора HopeLang

---

## Обзор модуля

Фронтенд — первая фаза компилятора. Цель: **превратить исходный текст программы (`.hope`) в строго типизированное семантическое дерево (AST)**, очищенное от синтаксического шума, и передать его следующим фазам:
* **Semantic Analysis:** проверка типов, таблицы символов, областей видимости.
* **Backend:** генерация байт-кода `.hbc` для виртуальной машины.

### Контракт модуля
* **Вход:** Исходный код на языке HopeLang в виде строки (`String`).
* **Выход:** Корневой узел дерева `SourceNode`, содержащий все декларации, типы, функции и обработчики.

---

## Архитектурный конвейер

Процесс обработки исходного кода делится на 4 последовательных шага:

```text
        [ Исходный код (.hope) ]
                    │
                    ▼ 
     1. Лексический анализ (CharStreams -> HopeLangLexer)
                    │ [ Поток токенов ] (CommonTokenStream)
                    ▼ 
     2. Синтаксический анализ (HopeLangParser)
                    │ [ Дерево разбора / CST ] (Concrete Syntax Tree)
                    ▼ 
     3. Трансляция (AstBuilderVisitor)
                    │ [ Абстрактное дерево / AST ] (AstNodes.kt)
                    ▼ 
     4. Визуализация (AstPrinter.kt)
```
│  - результат
▼
### Ключевые архитектурные паттерны:
1. **Фасад — `FrontendPipeline`:**  
   Скрывает все внутренности ANTLR (потоки символов, лексеры, буферы токенов, парсер) за одним чистым вызовом: `FrontendPipeline.parse(sourceCode): SourceNode`.
2. **Посетитель — `AstBuilderVisitor`:**  
   Разделяет структуры данных ANTLR и логику конструирования AST. Возвращает готовые иммутабельные узлы снизу вверх по стеку рекурсии без использования мутабельного глобального состояния.
3. **Алгебраические типы данных — `AstNodes.kt`:**  
   Иерархия узлов AST построена на `sealed interface`. Это гарантирует исчерпывающую проверку вариантов (`when` без `else`) на этапах семантики и генерации кода.
4. **Fail-Fast стратегия обработки ошибок:**  
   Стандартный механизм ANTLR (мягкое восстановление и попытка продолжить разбор при ошибке) отключен. Лексер и парсер снабжены строгими листенерами, которые немедленно выбрасывают `HopeSyntaxException` с указанием точной строки и колонки ошибки.

## Детальный разбор компонентов и кода

### Грамматика (`src/main/antlr/.../HopeLang.g4`)
Спроектирована под язык симуляции и содержит следующие ключевые пункты.
* **Блочный синтаксис:** Блоки закрываются ключевым словом `end`.
* **Явная типизация:** Синтаксис `of typeRef` (например, `var env of Environment`).
* **Реактивность:** На уровне грамматики заложены обработчики `on start`, `on Event(...)`, а также таймеры симуляции `every <duration>` и `at <duration>`.
* **Встроенные единицы времени:** Время — встроенный тип языка. Конструкция `durationLiteral` распознает единицы измерения времени (`ms`, `sec`, `min`, `hour`, `day`) как единый литерал (`1 min`, `3 hour`).
* **Слоистые выражения:** Приоритеты операций заданы строгой иерархией правил.

---

### Узлы дерева AST (`AstNodes.kt`)
Чистая модель предметной области.

* **Корневая структура:** `SourceNode(programName, declarations)`.
* **Декларации (`TopLevelDeclNode`):**
    * `ConstDeclNode`, `GlobalVarDeclNode` — глобальные данные.
    * `StructDeclNode`, `EnumDeclNode` — пользовательские типы.
    * `EventDeclNode` — шина событий.
    * `FunctionDeclNode` — императивные процедуры (`def`).
    * `StartHandlerNode`, `EventHandlerNode`, `EveryHandlerNode`, `AtHandlerNode` — реактивные обработчики.
* **Инструкции (`StmtNode`):** `AssignmentStmtNode`, `IfStmtNode`, `WhileStmtNode`, `ForStmtNode`, `EmitStmtNode`, `ExprStmtNode`, `ReturnStmtNode`.
* **Выражения (`ExprNode`):** бинарные/унарные операции, литералы, а также специализированные узлы доступа:
    * `FieldAccessExprNode` (`target.field`)
    * `IndexAccessExprNode` (`target[index]`)
    * `CallExprNode` (`function(args)`)

---

### Транслятор (`AstBuilderVisitor.kt`)
Класс преобразует сгенерированные ANTLR контексты (`Context`) в узлы `AstNodes`.

**Инженерные фичи реализации:**
1. **Свёртка постфиксных цепочек (Postfix Folding):**  
   Выражения вида `houses[i].temperature` или `push(issues, issue)` парсер считывает как базовый токен и список суффиксов (`postfixSuffix`). Визитор сворачивает их в глубоко вложенные семантические узлы:
   ```kotlin
   // Было: primary="houses", suffix1="[i]", suffix2=".temperature"
   // Стало: FieldAccess(target = IndexAccess(target = houses, index = i), fieldName = "temperature")
   ```
2. **Универсальный разбор бинарных слоев:**  
   Правила вида `A : B (OP B)*` обрабатываются циклом с аккумулятором, что сохраняет левую ассоциативность операций (`1 + 2 + 3` $\to$ `((1 + 2) + 3)`).
3. **Чистый маппинг If-Elif-Else:**  
   Поскольку грамматика допускает цепочки `elif`, визитор группирует условия и тела веток в аккуратный список `IfBranchNode(condition, body)`, а блок `else` сохраняет опциональным списком инструкций.

---

### Визуализатор (`AstPrinter.kt`)
Утилита форматирования AST в человекочитаемое древовидное представление с псевдографикой (`├──`, `└──`). Позволяет разработчикам визуально валидировать структуру дерева без необходимости подключать отладчик.
