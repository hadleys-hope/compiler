# BACKEND.md: Архитектура backend компилятора HopeLang

## Обзор модуля

Backend преобразует стековый **IR в байткод `.hbc`**. Он не разбирает исходный текст,
не заменяет семантический анализ и не исполняет программу.

- **Вход:** `IrProgram` — функции, структуры, globals, события и обработчики.
- **Выход:** проверенный `HbcModule`, массив байтов или файл HBC.
- **Интеграция:** внешний слой AST → IR передаёт разрешённые имена, типы и локальные слоты.
  Классы AST и frontend не входят в этот модуль.

## Архитектурный конвейер

```text
IrProgram
    → раскрытие DefaultValue и генерация initializer-функций
    → разрешение полей, типов, функций и метаданных
    → кодирование инструкций, пула констант и переходов
    → HbcVerifier
    → HbcModule → сериализация / запись .hbc
```

Обратный путь для проверки и диагностики: `.hbc → HbcReader → HbcVerifier → HbcDisassembler`.

## Основные компоненты

| Файл | Назначение |
|---|---|
| `Ir.kt` | Контракт входа: объявления, инструкции, метки, обработчики |
| `HbcBackend.kt` | Генерация значений по умолчанию, сборка байткода и безопасная запись файла |
| `HbcFormat.kt` | Типы, константы, опкоды, таблицы HBC и точное преобразование времени |
| `HbcVerifier.kt` | Общий декодер, проверки таблиц, инструкций и графа управления |
| `HbcReader.kt` | Строгое чтение двоичного формата |
| `HbcDisassembler.kt` | Листинг с метаданными, инструкциями и адресами переходов |
| `BackendExample.kt` | Исполнимый через тестовую VM пример функции `sumTo(n)` |

## Поддерживаемые конструкции

- **Функции и управление:** локальные слоты, арифметика, сравнения, вызовы, возвраты и переходы.
  Внешние функции разрешает host. Короткое замыкание логических операций задаётся переходами.
- **Структуры:** `IrStruct`, типизированные поля, создание, чтение и запись полей.
  `NewStruct` принимает значения всех полей в порядке объявления.
- **Массивы и `list<T>`:** создание, вложенная индексация, изменение элементов, длина;
  для списков — добавление и удаление с возвратом удалённого элемента.
- **Globals:** тип, изменяемость, initializer-функция и порядок объявлений.
  `const` требует явного initializer и запрещает переприсваивание.
- **События:** сигнатуры, `Emit`, функции обработчиков и порядок регистрации.
- **`on start`, `every`, `at`:** ссылки на функции и временные метаданные для VM.

## Значения по умолчанию и ссылки

`IrGlobal(initializer = null)` автоматически получает initializer по типу.
`DefaultValue(type)` создаёт такое же значение внутри функции; для локальной переменной
результат сохраняется через `StoreLocal`. У `IrField` можно указать собственную
initializer-функцию без параметров, возвращающую значение поля.

| Тип | Значение по умолчанию |
|---|---|
| `int`, `real`, `time` | Ноль соответствующего типа |
| `bool` / `string` | `false` / пустая строка |
| `list<T>` | Новый пустой список |
| Массив | Новый массив с отдельно созданным значением каждого элемента |
| Структура | Initializer каждого поля либо его значение по умолчанию |

Фабрики переиспользуют код, но каждый вызов создаёт новые изменяемые объекты.
Для массивов `NewArrayWithInitializer` вызывает фабрику на каждый индекс:
байткод не увеличивается пропорционально размеру массива.
Неявные циклы конструирования отклоняются; рекурсия через пустой список или массив допустима.
Глубина описания типа и вложенного конструирования ограничена 64 уровнями.

Структуры, массивы и списки имеют **ссылочную семантику**: присваивание сохраняет ссылку.
`const` фиксирует привязку имени, но позволяет менять содержимое объекта.
Индексы начинаются с нуля; типы элементов и границы при исполнении проверяет VM.

## Контракт запуска и времени

1. VM инициализирует globals один раз, по порядку объявлений. Обращение к ещё
   не инициализированному global — ошибка; неудачный initializer прерывает запуск.
2. Завершение инициализации задаёт начало отсчёта времени. VM регистрирует обработчики
   и выполняет все `START` один раз, в порядке таблицы.
3. События из initializer-функций и `START` накапливаются в FIFO-очереди.
   После всех `START` VM обрабатывает эту очередь, затем `AT 0`.
   Обработчики одного события вызываются по порядку регистрации.
4. `AT t` срабатывает один раз через `t >= 0` миллисекунд от начала отсчёта.
   `EVERY p` впервые срабатывает через `p > 0`, затем в моменты `2p, 3p, …`.
   Пропущенные тики объединяются в один вызов; следующее срабатывание сохраняет исходную
   временную сетку. Один обработчик не запускается параллельно самому себе.

`HbcTime.milliseconds("1.5", HbcTimeUnit.SEC)` возвращает `1500L`.
Дробные миллисекунды, переполнение и нечисловые значения отклоняются.
Перегрузка для `Double` поддерживает внешний AST, но не восстанавливает потерянную в нём
точность; предпочтителен исходный десятичный текст. Планирование выполняет **VM / scheduler**.

## Контракт байткода и проверки

Каждая функция начинает с пустого стека; параметры занимают первые локальные слоты.
Аргументы и элементы конструкторов помещаются слева направо.
`CALL` всегда возвращает одно значение, включая unit; `EMIT` результата не оставляет.
`Return()` требует пустого стека, `Return(true)` — ровно одного значения.
Переходы используют знаковое смещение `i32` от конца инструкции до начала целевой.

Версия формата остаётся **HBC v1**. Все числа big-endian:
`HBC\0 → version=1 → constants → functions → необязательная секция META`.
`META` содержит таблицы типов, структур, globals, событий и обработчиков.
Таблицы и строковые данные ограничены `u16`; строки используют строгий UTF-8.
Типы и порядок операндов заданы в `HbcFormat.kt`, `HbcReader.kt` и комментариях `IrInstruction`.

Прежние файлы без `META` читаются, старые программы сохраняют прежние байты.
При наличии `META` обращения к globals и событиям требуют объявлений.
Новые инструкции и таблицы требуют соответствующей поддержки VM.

Verifier проверяет ссылки, имена, сигнатуры обработчиков и initializer-функций,
запрет записи в `const`, цели переходов, нехватку значений и высоты стека на слияниях.
Полная проверка типов выражений остаётся в семантическом анализаторе.
Запись проверяет весь модуль до изменения выходного файла, затем заменяет его через временный файл.

## Использование и проверка

```kotlin
val program = IrProgram(
    functions = listOf(IrFunction("tick", 0, 0, listOf(
        IrInstruction.LoadGlobal("count"), IrInstruction.Push(HbcConstant.IntValue(1)),
        IrInstruction.Binary(BinaryOperation.ADD), IrInstruction.StoreGlobal("count"),
        IrInstruction.Return()
    ))),
    globals = listOf(IrGlobal("count", HbcType.IntType)), // начальное значение 0
    handlers = listOf(IrHandler.Every(HbcTime.milliseconds("1", HbcTimeUnit.SEC), "tick"))
)
val bytes = HbcBackend.compileToBytes(program)
val module = HbcReader.read(bytes)
val listing = HbcDisassembler.disassemble(module)
```

Также доступны `HbcBackend.compile(program)` и `HbcBackend.write(program, path)`.
Для сборки нужен JDK 21. Из каталога `compiler`:

```powershell
.\gradlew.bat test
.\gradlew.bat run --args="--demo build/example.hbc"
.\gradlew.bat run --args="--dump build/example.hbc"
```

Тесты проверяют эталонные байты, round-trip, повреждённые файлы, стек, defaults,
вложенные объекты, globals и порядок запуска на ограниченном тестовом интерпретаторе.
Production-VM, реальные часы, AST → IR и отдельное представление enum в этот модуль не входят.
